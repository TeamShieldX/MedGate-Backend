## 1. Overview

Electronic Health Records (EHR) contain sensitive clinical diagnoses, notes, and personally identifiable information (PII). In modern healthcare systems, different clinical and administrative personnel require varying degrees of data access. Granting broad access creates severe privacy and security risks, while traditional perimeter-only security fails to protect patient confidentiality internally.

**MedGate** is a zero-trust, role-based access control (RBAC) and field-level data redaction gateway for electronic health records. Every single request to clinical data passes through a centralized access decision engine that enforces least-privilege security policies, strips unauthorized fields dynamically in-memory, and writes an immutable, tamper-evident SHA-256 hash-chained audit log entry.

The data layer is built on open-source synthetic clinical records generated by **Synthea** (FHIR/relational model), ensuring zero real-patient privacy exposure while supporting production-scale clinical schemas.

## 2. Core Features & Linear Milestones

| Milestone | Component | Description |
| :--- | :--- | :--- |
| **SHI-5** | **Access Control Engine (RBAC)** | Data-driven role-permission matrix with default-deny security and dynamic field-level redaction. |

| **SHI-10** | **Scalability & Performance Benchmarks** | Stress and latency testing across 1,000+ operations and datasets of 50 to 500+ records. |

## 3. Architecture & Request Flow

```
[ Client Request ] (Headers: x-user-role, x-user-id, x-user-name)
       │
       ▼
[ Express API Gateway ] ──► [ Access Control Guard Middleware ]
                                       │
                                       ▼
                       evaluateAccess(user, resource, action)
                                       │
                ┌──────────────────────┴──────────────────────┐
                ▼                                             ▼
     [ RBAC Engine (SHI-5) ]                     [ Audit Logger (SHI-8) ]
       • Validate role                             • Generate event payload
       • Evaluate permissions                      • Compute SHA-256 hash:
       • Default-deny logic                          SHA256(Payload + PrevHash)
       • Human-readable reason                     • Write to audit_logs table
                │
        ┌───────┴───────────────────────┐
        ▼                               ▼
  [ If DENIED ]                   [ If GRANTED ]
  Return 403 Forbidden            Execute Database Query
  { allowed: false, reason }             │
                                         ▼
                          [ Patient Data Layer (SHI-6) ]
                            • Neon PostgreSQL query
                            • Relational graph assembly
                                         │
                                         ▼
                          [ Dynamic Redaction (SHI-5) ]
                            • Strip unauthorized clinical/PII fields
                                         │
                                         ▼
                          [ Redacted Clinical Response (200) ]
```

## 4. Role-Based Field Redaction Matrix

MedGate evaluates field visibility dynamically on every request based on the caller's role:

| Resource / Field | Doctor | Nurse | Receptionist | Researcher | Administrator |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Patient ID (`id`)** | Visible | Visible | Visible | Visible | Visible |
| **Names (`firstName`, `lastName`)** | Visible | Visible | Visible | **Redacted** (De-identified) | Visible |
| **Contact (`address`, `phone`)** | Visible | Visible | Visible | **Redacted** (De-identified) | Visible |
| **Demographics (`birthDate`, `gender`)** | Visible | Visible | Visible | Visible | Visible |
| **Primary Condition** | Visible | Visible | **Redacted** | Visible | Visible |
| **Confidential Clinical Notes** | Visible | **Redacted** | **Redacted** | **Redacted** | Visible |
| **Medications** | Visible | Visible | **Redacted** | Visible | Visible |
| **Observations (Vitals / Labs)** | Visible | Visible | **Redacted** | Visible | Visible |
| **Appointments** | Visible | Visible | Visible | **Redacted** | Visible |
| **Audit Logs (`GET /audit-log`)** | **Denied (403)** | **Denied (403)** | **Denied (403)** | **Denied (403)** | **Granted (200)** |

## 5. Database Architecture

Deployed to **Neon Serverless PostgreSQL**, the relational schema comprises 11 tables:

- **`users`**: System user credentials and assigned RBAC roles.
- **`patients`**: Core demographics and primary clinical attributes.
- **`encounters`**: Clinical encounters, classes, providers, and timestamps.
- **`diagnoses`**: SNOMED/ICD diagnoses codes, descriptions, and onset dates.
- **`medications`**: Active/historical prescriptions, dosages, and frequencies.
- **`observations`**: Clinical vitals, lab test measurements, and units.
- **`allergies`**: Recorded allergens, reaction types, and criticality levels.
- **`procedures`**: Surgical and medical procedure records.
- **`immunizations`**: Vaccine administration records and dates.
- **`appointments`**: Scheduling, provider assignments, and visit statuses.
- **`audit_logs`**: Append-only audit records with SHA-256 hash chains (`id`, `user_role`, `action`, `resource`, `result`, `reason`, `hash`, `prev_hash`, `timestamp`).

## 7. API Reference

### Base URL & Health Check
- **Base URL:** `http://localhost:5000`
- **Health Check:** `GET /health`

### Authentication & Role Context Headers
All protected endpoints accept role context via HTTP headers (or `?role=` query parameter):
- `x-user-role`: `Doctor` | `Nurse` | `Receptionist` | `Researcher` | `Administrator`
- `x-user-id`: Caller user ID (e.g. `doc-101`)
- `x-user-name`: Caller display name (e.g. `dr_smith`)

### Endpoints

#### 1. Authentication
- `POST /auth/login`
  - **Body:** `{ "role": "Doctor", "username": "dr_smith" }`
  - **Response:** `200 OK` with user session details. Invalid roles return `400 Bad Request`.

#### 2. Patients
- `GET /patients?limit=25&offset=0`
  - Returns a list of patients dynamically redacted according to the active role.
- `GET /patients/:id`
  - Returns the full patient profile with relational graphs (encounters, diagnoses, medications, observations, allergies, appointments) filtered per the active role.

#### 3. Audit Log
- `GET /audit-log?limit=50&offset=0&role=Doctor&result=GRANTED`
  - **Administrator Only.** Non-administrators receive `403 Forbidden`.
  - Returns chronological audit log records alongside `integrity.tamperEvidentChainValid: true`.

## 8. Getting Started

### Prerequisites
- **Node.js** v18+ (tested on v22+)
- **Neon PostgreSQL** database connection string (or local PostgreSQL)

### 1. Installation
```bash
cd MedGate-Backend
npm install
```

### 2. Environment Configuration
Create a `.env` file in the root directory (based on `.env.example`):
```env
PORT=5000
CLIENT_URL=http://localhost:5173
DATABASE_URL=postgresql://neondb_owner:<password>@<neon-host>/neondb?sslmode=require
```

### 3. Database Migration & Batch Seeding
Seed the database with official Synthea patient records and relational clinical graphs:
```bash
npm run seed
```

### 4. Running the Server
```bash
# Development mode (nodemon)
npm run dev

# Production start
npm start
```
The server will start at `http://localhost:5000`.
